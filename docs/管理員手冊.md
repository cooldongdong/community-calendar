# 管理員手冊

[← 回 README](../README.md)

管理員是有這個 repo 寫入權限的人。這份文件寫的是管理員日常要做的事；同步程式怎麼運作見[技術說明](技術說明.md)。

## 最重要的一條：共筆還在就改共筆

資料錯了，**先看那場活動還在不在共筆上**：

- **還在** → 直接改共筆。隔天同步就會跟上，不用碰這個 repo
- **已經被清掉了** → 在 `overrides/{id}.json` 修（見下一節）

修正檔寫的欄位會**一直蓋過共筆**，共筆之後再改也不會反映出來，所以只在共筆沒地方改時才用。

## 修正檔：`overrides/{id}.json`

管理員做的事都寫在這裡。同步程式不會動它。

```json
{
  "hidden": true,
  "jothon": true,
  "series": "hackathon",
  "set": { "title": "正確的標題", "start_time": "19:00" },
  "note": "為什麼這樣改，給下一個管理員看"
}
```

| 欄位 | 作用 |
|---|---|
| `hidden` | `true`＝下架：網站與日曆都不出現，活動頁變成 404。資料仍保留，改回 `false` 就恢復 |
| `jothon` | `true`＝揪松主辦，放進揪松日曆；`false`＝確認不是，不再提醒 |
| `set` | 蓋掉共筆解析出來的欄位 |
| `series` | 指定系列（`config/series.json` 的 slug），`null`＝不屬於任何系列。不寫就從標題自動判斷 |
| `note` | 備註，不會顯示在網站上 |

每一欄都可以省略。活動頁上的「修正檔」連結會直接開到這場活動的檔案。

**不要直接改 `events/{id}.json`**：活動還在共筆上的話，共筆下次一改就會整筆重寫。

### 揪松主辦只看修正檔

共筆上寫的「主辦：揪松」不算數：共筆誰都能寫，而揪松日曆是帶著揪松名義發出去的。標題看起來像揪松活動（黑客松、AI Monday、放輕松、跑咖松）但還沒確認的，會列在資料檢查 issue 裡，請建立修正檔寫 `"jothon": true` 或 `false`。

例外是 AI Monday：揪松團自己維護的 [AI Monday 資料](https://data.civictech.tw/v0/aimonday/events.json)同一天也有一場，就自動當成揪松主辦。

## 網站上的「修改這筆」與「新增活動」

一般人不用碰 GitHub 的檔案：

1. 在活動頁按「修改這筆」（或到 `/submit/` 新增活動），在網站上填好
2. 按「到 GitHub 送出」，會打開一張欄位都填好的 issue，按 Submit
3. 自動轉成 PR，並在 issue 留言附上 PR 連結
4. **管理員看過後合併**，網站與日曆幾分鐘內更新

修改會寫進 `overrides/{id}.json`；新增的活動放在 `manual/`，之後共筆上也出現同一場時，以共筆那筆為準。

沒有 GitHub 帳號的人，表單上有「寄信給揪松團」，內容會幫他填好（信箱在 `config/site.json`）。

### 批次修改：一次改很多場的系列、揪松主辦，或一起拿掉

1. 打開 [活動列表加上 `?admin=1`](https://g0v.github.io/community-calendar/events/?admin=1)，進入管理模式（這台瀏覽器會記住；`?admin=0` 或標題旁的「離開」關掉）
2. 用搜尋與篩選找到要改的活動，**點活動就會選取**；Shift＋點選一段，`Esc` 全部取消。列表上方的勾勾是「全選目前顯示的」
3. 在底部工具列選要改成什麼（系列、揪松主辦、拿掉），按「送出…」，寫理由，按「到 GitHub 送出」，再按 Submit
4. 自動開**一個** PR，每場一列「現在 → 改成」；合併後生效

開始選了之後，點活動標題也算選取，不會打開活動頁；要打開就用 Cmd／Ctrl＋點。

#### 清掉「共筆已移除」的活動

管理模式的篩選多一個「只看共筆已移除」：活動日還沒到就從共筆上消失的。這些多半該拿掉，但**光看消失分不出是取消、誤刪，還是改名重貼**，所以不會自動選，要一場一場看：

- 每場底下會寫「同一天共筆上還有：…」。有一場名字很像的，就是改名重貼，拿掉這筆舊的沒問題
- 同一天共筆上什麼都沒有的，比較可能是取消，也可能是誤刪。不確定就去共筆的修改歷史查
- PR 裡也會附上同樣的資訊，審 PR 的人不用回網站查

兩個限制：

- **只能改系列、揪松主辦、拿掉。** 這三樣本來就以修正檔為準。地點、時間這些共筆上有的內容不開放批次：一次蓋掉很多場，之後共筆改了也不會有人發現
- **只有 repo 的協作者（有寫入權限）送出的才會開 PR**，其他人送的會在 issue 上留言說明並擋下來。管理模式本身誰都打得開，它只是讓一般訪客看不到勾選框，不是權限控管

一次最多 300 場，再多請分批。

## 有人回報問題時

網站每一場活動都有「回報問題」，會開一張 issue。處理方式：

- 資料錯了 → 共筆還在就改共筆；共筆已經刪了，就在修正檔用 `set` 修
- 活動取消、內容有害或不適合 → 修正檔寫 `"hidden": true`

改完 push 到 main，幾分鐘後網站與日曆就會更新。訂閱的日曆要看各家軟體多久重新抓一次，通常是數小時內。

## 資料檢查 issue

每天同步完，需要人看的地方會彙整成一張標著「資料檢查」的 issue。

| 等級 | 意思 |
|---|---|
| 🔴 錯誤 | 這次沒有更新資料，網站停在上一版。處理好才會恢復 |
| 🟡 提醒 | 資料照常更新，但共筆上有地方看起來寫錯了（漏了 `---`、時間和地點對調、日期對不上等） |

**怎麼處理：**

1. **改共筆**。提醒裡的「共筆第 N 行」指的是共筆原始 Markdown 的行號
2. **等下一次同步**。全部處理好，issue 會自動關閉；還有剩的，issue 會更新內文並留言
3. **不要手動關這張 issue**。問題還在的話，下一次同步會另開一張新的

在 issue 底下留言不會影響任何事，同步程式只看共筆現在長什麼樣子。

## 想馬上更新，不等明天

每天台灣時間 04:30 自動同步一次，GitHub 的排程常延遲幾個小時。想馬上更新：到 [Actions](https://github.com/g0v/community-calendar/actions/workflows/sync.yml) →「同步、建置、部署與資料檢查」→ Run workflow。

push 到 main 也會觸發一次。

## 加一份訂閱日曆

改 [`config/feeds.json`](../config/feeds.json)：一段一份，用「揪松主辦」「系列」「標題關鍵字」組合條件。

系列的判斷規則在 [`config/series.json`](../config/series.json)（標題關鍵字），只放揪松自己辦的系列；揪松主辦、但不屬於任何系列的，自動歸到「其他揪松活動」。

兩個檔案都不用會寫程式。日曆只收日期確定到「哪一天」的活動；分城市辦的大松，每個城市一個事件。

## 共筆範本

放在共筆最上面，收在折疊區裡。請大家照著填，同步程式最好認：

```markdown
:::warning
:::spoiler 這是一個活動範本
---
2026-mm-dd 活動名稱
- 時間：19:00-21:00
- 地點：場地名稱（線上活動寫「線上」）
- 地址：完整地址
- 主辦：主辦單位
- 報名：https://…
- 線上：https://…（直播或線上會議）
- 共筆：https://…
- 活動頁：https://…（官網、FB 活動頁）
---
:::
```

- 每筆活動前後用 `---` 隔開；第一行是日期＋活動名稱，跨天寫 `2026-11-07~11-08`
- **有報名表或共筆的話一定要附**，那是辨認「同一場活動」最可靠的依據
- 分城市辦的活動，用「- 高雄場」往下縮排寫各場的時間、地點
- 舊的寫法（`10/14 週三晚上 …`、`2026/11/08 Sun. …` 等）仍然認得，不必改
- 只知道月份、還沒定日期的活動，寫在那個月份底下就好。網站上會列出來，但不會放進訂閱日曆
