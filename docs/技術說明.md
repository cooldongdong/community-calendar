# 技術說明

[← 回 README](../README.md)

同步怎麼運作、資料在哪、為什麼這樣設計，以及本機開發。管理員日常要做的事見[管理員手冊](管理員手冊.md)。

## 整體流程

```
揪松團共筆（g0v.hackmd.io）
  │ 每天台灣時間 04:30，GitHub Actions 跑 scripts/sync.mjs
  ▼
events/{id}.json   一場活動一個檔案，有變就 commit 回 main
  │ 套上 overrides/（管理員修正）、併進 AI Monday 的資料
  ▼
網站 ＋ .ics 日曆檔   重新建置、部署到 GitHub Pages
```

同步結果寫進 `report.json`，需要人看的地方再彙整成「資料檢查」issue（`scripts/data-check-issue.sh`）。

## 跟共筆的關係：累積，不是鏡像

共筆會被定期清掉過期的活動，所以這裡**不是**「共筆長怎樣、資料就長怎樣」：

- 共筆上還在的活動：有改就跟著更新
- 共筆上不見的活動：**留著**，標上 `in_source: false` 與消失的日期。網站與日曆照常顯示
- 活動日還沒到就從共筆消失的（可能取消、也可能誤刪）：照常顯示，但標「共筆已移除」
- **一筆都不自動刪除**。要下架用修正檔的 `hidden`

## 共筆從哪裡讀

g0v.hackmd.io 前面有 AWS 的防火牆，對 GitHub Actions 的機器一律回人機驗證頁（HTTP 405），所以同步程式依序試：

1. 直接從 g0v.hackmd.io 下載：在一般電腦或 VPS 上跑時會成功
2. [g0v-data/g0v-hackmd-archive](https://github.com/g0v-data/g0v-hackmd-archive)：Ronny 每小時爬一次的 g0v HackMD 備份。從 GitHub Actions 讀得到；備份超過 3 天沒更新會在資料檢查 issue 提醒
   - 「大松小松活動訊息」在備份裡的那一頁：[`notes/N3EnvC7ATSG-r71zuleuyQ.md`](https://github.com/g0v-data/g0v-hackmd-archive/blob/main/notes/N3EnvC7ATSG-r71zuleuyQ.md)（[修改歷史](https://github.com/g0v-data/g0v-hackmd-archive/commits/main/notes/N3EnvC7ATSG-r71zuleuyQ.md)）

不嘗試繞過人機驗證，那是 HackMD／g0v 那邊的決定。`report.json` 的 `read_from` 記錄這次讀自哪裡。

## 怎麼認出「同一場活動」

共筆誰都能改，標題、日期都可能被改，所以依可信度依序比對：

1. 報名／共筆／活動頁的網址相同，而且這個網址在共筆上只出現在這一筆（同一張報名表被好幾場共用是常態）
2. 同一天，且標題相似（一個包含另一個、或同一個固定系列，也算）
3. 標題完全相同、日期不同（改期）：當成同一場，另外報一條提醒

都對不上就當成新的一筆。**寧可多一筆讓人合併，也不要把兩場不同的活動默默合成一筆。**

## 解析：容錯，但不默默修

共筆的寫法很多種，認得出來的都接受（日期至少六種寫法、同義欄名、日文欄名）。看起來有問題的地方（漏了 `---`、時間和地點的值對調、標題的日期跟「時間」欄對不上），會照原樣收進來，另外記一條提醒。提醒會出現在活動頁，也會進資料檢查 issue。

判斷全部是寫死的規則（`scripts/parse.mjs`），沒有用 AI：同樣的共筆永遠得到同樣的結果。

## 資料在哪

| 路徑 | 內容 |
|---|---|
| `events/{id}.json` | 一場活動一個檔案，由同步程式寫入。**這個檔案在 GitHub 上的 History 就是那場活動的修改紀錄** |
| `overrides/{id}.json` | 管理員的修正，人工維護。同步程式不會動它 |
| `manual/` | 從網站「新增活動」送進來的活動 |
| `/events.json`（網站上） | 開放資料：套用修正後、網站上看得到的每一筆 |
| `/report.json`（網站上） | 最近一次同步的檢查結果 |

`id` 在第一次看到這場活動時決定，之後不會變（就算標題、日期被改），網址與日曆的 UID 都靠它。所以 id 開頭的日期可能跟活動現在的日期不同，以檔案裡的 `date_start` 為準。

內容沒變就不寫檔，所以 `events/` 的 git 歷史只記真的有改的時候。

## 與 AI Monday 的資料合併

[AI Monday](https://g0v.github.io/AI-Monday/) 工作小組的資料（[data.civictech.tw](https://data.civictech.tw/v0/aimonday/events.json)）不存在這裡，建置時讀取。

同一場活動兩邊都有時（同一天、同一個系列），只顯示一筆：時間與講者以 AI Monday 的資料為準，並連到 AI Monday 的講題頁。講題、講者、錄影這些「講了什麼」留在 AI Monday 網站；「什麼時候、在哪」都在這裡。AI Monday 的訂閱用它自己原本的 `calendar.ics`，不另外產生。

## 搜尋與篩選

活動頁（`/events/`）可以搜尋活動名稱、地點、講者與共筆原文，並依時間（近期／過去）、揪松主辦、系列、地點（縣市或線上）篩選。條件會寫進網址，可以直接分享，例如 `?series=hackathon&when=all`。

系列、縣市、線上是程式從標題與地點推出來的（`scripts/facets.mjs`），推不出來就不標。

## 補回來的過去活動

每日同步從 2026-10-09 開始。在那之前就被清掉的活動，是從共筆的舊版本補回來的（`scripts/backfill.mjs`）：

- **HackMD 版本歷史**：公開的共筆不用登入就讀得到（`/{note id}/revision`），從 2024-12-15 起約 500 版，幾乎每次編輯都有一版
- **網路檔案館**（Wayback Machine）：2025-01 起 21 份存檔，是第一輪補資料用的，版本歷史涵蓋得更完整

這些資料帶有 `archive` 欄位，記錄最早與最晚出現在哪一版。2024-12-15 以前的共筆沒有版本可以讀。

在活動日之前就從存檔裡消失的，多半是改期或取消前的舊計畫，網站會標「共筆已移除」，月曆上畫刪除線。

## 本機開發

需要 Node.js 22.12 以上。

```bash
npm install
npm run sync     # 讀共筆、更新 events/、產生 report.json
npm run dev      # 開發伺服器
npm run build    # 輸出靜態檔到 dist/
```

用本機的共筆檔測試：`SOURCE_FILE=path/to/event.md TODAY=2026-10-09 npm run sync`
模擬 GitHub Actions 改讀備份：`FORCE_ARCHIVE=1 npm run sync`

### 預覽站：測網站送出的修改，又不碰正式 repo

fork 一份就是預覽站。`sync.yml` 在 fork 上只建置與部署到 fork 自己的 GitHub Pages（`你的帳號.github.io/community-calendar/`），不讀共筆、不 commit、不開資料檢查 issue；網站頂端掛「這是預覽版」橫幅、不讓搜尋引擎收錄，「到 GitHub 送出」開到 fork 自己。

一次性設定：

1. fork 的 Settings → Pages → Source 選「GitHub Actions」
2. 開 Issues，建「修改活動」「新增活動」「批次修改」三個標籤
3. Actions 頁打開 workflow（fork 預設是關的），Settings → Actions → Workflow permissions 選 read and write、允許開 PR

之後把要測的分支推成 fork 的 `main`，幾分鐘後預覽站就是那個分支的樣子；在 fork 用網站送修改、合併 PR，網站也會跟著更新。**GitHub 的 issue 表單與 issue 觸發的 workflow 永遠用預設分支的版本**，所以要測表單或 workflow 的改動，一定要推成 fork 的 `main`，推別的分支不算數。

不想 fork、只想在本機或別的地方看畫面：

```bash
PUBLIC_PREVIEW=1 PUBLIC_REPO=你的帳號/community-calendar BASE=/ npm run build
```

`PUBLIC_REPO` 是「到 GitHub 送出」開 issue 的 repo，預設 `g0v/community-calendar`，**預覽一定要換掉**，不然測試 issue 會開進正式 repo。

| 檔案 | 做什麼 |
|---|---|
| `scripts/parse.mjs` | 共筆 Markdown → 一筆一筆活動。只做文字轉換，不碰檔案與網路 |
| `scripts/sync.mjs` | 讀共筆、比對既有資料、寫 `events/` 與 `report.json` |
| `scripts/resolve.mjs` | 套上 `overrides/`、判斷揪松主辦、併進 AI Monday 的場次。同步與網站共用 |
| `scripts/facets.mjs` | 從標題與地點推出系列、縣市、線上 |
| `scripts/backfill.mjs` | 從共筆的 HackMD 版本歷史（或網路檔案館）補回過去的活動，可重複跑 |
| `scripts/issue-to-pr.mjs` | 把網站送出的「修改／新增活動」issue 轉成 PR |
| `scripts/data-check-issue.sh` | 把 `report.json` 同步成「資料檢查」issue |
| `src/lib/ics.ts` | 產生日曆檔 |
| `.github/workflows/sync.yml` | 每日同步、建置、部署 |
